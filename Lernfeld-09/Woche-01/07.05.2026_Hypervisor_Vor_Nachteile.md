# 🖥️ Server-Virtualisierung & Hypervisor

> **Thema:** Das Konzept der Server-Virtualisierung (VMs)  
> **Schwerpunkt:** Hypervisor – Definition, Typen, Vor- und Nachteile

---

## 📌 1. Was ist Virtualisierung?

**Server-Virtualisierung** ist eine Technologie, bei der ein physischer Server mithilfe von Software in mehrere **virtuelle Maschinen (VMs)** aufgeteilt wird. Jede VM verhält sich wie ein vollständiger, eigenständiger Computer mit eigenem Betriebssystem, eigenen Ressourcen und Anwendungen – obwohl sie alle auf derselben physischen Hardware laufen.

### Grundprinzip:
```
┌─────────────────────────────────────────┐
│         Physischer Server               │
│  ┌────────┐  ┌────────┐  ┌────────┐    │
│  │  VM 1  │  │  VM 2  │  │  VM 3  │    │
│  │ Linux  │  │Windows │  │ macOS  │    │
│  └────────┘  └────────┘  └────────┘    │
│           [  Hypervisor  ]              │
│           [ Hardware     ]              │
└─────────────────────────────────────────┘
```

---

## 📌 2. Was ist ein Hypervisor?

Ein **Hypervisor** (auch: **Virtual Machine Monitor / VMM**) ist eine Software- oder Firmware-Schicht, die es ermöglicht, mehrere Betriebssysteme gleichzeitig auf einer physischen Hardware auszuführen.

Der Hypervisor ist das **Herzstück der Virtualisierung** – er verwaltet und isoliert die virtuellen Maschinen und weist ihnen Hardware-Ressourcen zu:

| Ressource        | Aufgabe des Hypervisors                        |
|------------------|------------------------------------------------|
| **CPU**          | Zeitscheiben an VMs verteilen                  |
| **RAM**          | Speicher reservieren und isolieren             |
| **Speicher**     | Virtuellen Festplattenspeicher bereitstellen   |
| **Netzwerk**     | Virtuelle Netzwerkkarten & Switches verwalten  |

---

## 📌 3. Typen von Hypervisoren

### 🔷 Typ 1 – Bare-Metal Hypervisor (nativ)

Der Typ-1-Hypervisor läuft **direkt auf der Hardware**, ohne ein Host-Betriebssystem. Er hat direkten Zugriff auf die Hardwareressourcen.

```
┌───────────────────────────────────────────┐
│           Physische Hardware              │
│       [ Typ-1-Hypervisor (direkt) ]       │
│  ┌──────────┐  ┌──────────┐  ┌────────┐  │
│  │   VM 1   │  │   VM 2   │  │  VM 3  │  │
└───────────────────────────────────────────┘
```

**Beispiele:**
- VMware ESXi
- Microsoft Hyper-V (als eigenständige Rolle)
- KVM (Kernel-based Virtual Machine, Linux)
- Xen

**Einsatz:** Rechenzentren, Enterprise-Umgebungen, Cloud-Infrastrukturen

---

### 🔷 Typ 2 – Hosted Hypervisor (gehostet)

Der Typ-2-Hypervisor läuft **auf einem vorhandenen Host-Betriebssystem** und wird wie eine normale Anwendung ausgeführt.

```
┌───────────────────────────────────────────┐
│           Physische Hardware              │
│         [ Host-Betriebssystem ]           │
│       [ Typ-2-Hypervisor (App) ]          │
│  ┌──────────┐  ┌──────────┐              │
│  │   VM 1   │  │   VM 2   │              │
└───────────────────────────────────────────┘
```

**Beispiele:**
- Oracle VirtualBox
- VMware Workstation / Fusion
- Microsoft Virtual PC
- Parallels Desktop (macOS)

**Einsatz:** Entwicklung, Tests, Desktop-Nutzung, Heimanwender

---

### 🔷 Vergleich Typ 1 vs. Typ 2

| Merkmal              | Typ 1 (Bare-Metal)        | Typ 2 (Hosted)              |
|----------------------|---------------------------|-----------------------------|
| Läuft auf            | Direkt auf Hardware       | Auf Host-Betriebssystem     |
| Performance          | ⭐⭐⭐⭐⭐ Sehr hoch         | ⭐⭐⭐ Mittel                 |
| Sicherheit           | ⭐⭐⭐⭐⭐ Sehr hoch         | ⭐⭐⭐ Mittel                 |
| Einrichtung          | Komplex                   | Einfach                     |
| Ressourceneffizienz  | Sehr effizient            | Weniger effizient           |
| Typischer Einsatz    | Rechenzentren / Cloud     | Entwicklung / Tests         |

## 📌 4. Wichtige Begriffe rund um den Hypervisor

| Begriff              | Erklärung                                                                 |
|----------------------|---------------------------------------------------------------------------|
| **Host**             | Der physische Server, auf dem der Hypervisor läuft                       |
| **Guest / VM**       | Das virtuelle Betriebssystem, das auf dem Hypervisor läuft               |
| **Snapshot**         | Momentaufnahme des VM-Zustands zur schnellen Wiederherstellung           |
| **Migration**        | Verschieben einer laufenden VM auf einen anderen Host (Live-Migration)   |
| **vCPU**             | Virtueller Prozessorkern, der einer VM zugewiesen wird                   |
| **vRAM**             | Virtueller Arbeitsspeicher einer VM                                       |
| **Overcommitting**   | Mehr virtuelle Ressourcen zuweisen als physisch vorhanden sind           |
| **Cluster**          | Zusammenschluss mehrerer physischer Server unter einem Hypervisor        |
| **Emulation**        | Simulation fremder Hardware (langsamer als Virtualisierung)              |
| **Container**        | Leichtgewichtige Alternative zu VMs (z. B. Docker), teilen OS-Kernel    |

## 📌 5. Vorteile des Hypervisors / der Virtualisierung

### ✅ Ressourcenoptimierung
- Mehrere VMs teilen sich eine physische Hardware → **bessere Auslastung** der Server
- Verhindert „Server-Sprawl" (zu viele ungenutzte physische Server)

### ✅ Kostenersparnis
- Weniger physische Hardware erforderlich
- Geringere Strom-, Kühlungs- und Wartungskosten
- Weniger Rack-Platz im Rechenzentrum

### ✅ Isolierung & Sicherheit
- VMs sind voneinander **vollständig isoliert** – ein Absturz einer VM beeinflusst andere nicht
- Sicherheitsprobleme bleiben auf eine VM begrenzt

### ✅ Flexibilität & Skalierbarkeit
- Neue VMs können in **wenigen Minuten** erstellt werden
- Ressourcen (RAM, CPU) können dynamisch angepasst werden
- Einfaches Klonen und Kopieren von VMs

### ✅ Ausfallsicherheit & Hochverfügbarkeit
- **Live-Migration**: VMs können auf andere physische Server verschoben werden, ohne Ausfallzeit
- **Snapshots**: Schnelle Wiederherstellung bei Problemen
- Automatisches Neustart von VMs bei Hardwareausfall

### ✅ Einfaches Testen & Entwickeln
- Entwickler können verschiedene Betriebssysteme und Konfigurationen sicher testen
- Testumgebungen lassen sich schnell aufsetzen und löschen

### ✅ Disaster Recovery
- VMs können als Dateien gesichert und auf beliebige Hardware wiederhergestellt werden
- Schnellere Wiederherstellungszeiten (RTO) im Vergleich zu physischen Servern

---

## 📌 6. Nachteile des Hypervisors / der Virtualisierung

### ❌ Performance-Overhead
- Der Hypervisor selbst verbraucht Ressourcen (CPU, RAM)
- VMs erreichen nicht die **volle Performance** der physischen Hardware
- Besonders bei I/O-intensiven Workloads spürbar

### ❌ Komplexität
- Einrichtung und Verwaltung erfordert **Fachwissen**
- Netzwerkkonfiguration (virtuelle Switches, VLANs) ist komplex
- Lizenzierung kann kompliziert und teuer sein (z. B. VMware)

### ❌ Sicherheitsrisiken (VM Escape)
- Theoretisch kann ein Angreifer aus einer VM **ausbrechen** und den Hypervisor angreifen
- Der Hypervisor selbst wird zum **Single Point of Attack**

### ❌ Ressourcenkonkurrenz
- Viele VMs auf einem Host konkurrieren um CPU, RAM und I/O
- **Noisy-Neighbor-Problem**: Eine VM mit hoher Last beeinträchtigt andere VMs

### ❌ Lizenzkosten
- Enterprise-Hypervisoren wie VMware ESXi sind **sehr teuer**
- Betriebssystem-Lizenzen für jede VM sind separat erforderlich

### ❌ Hardwareabhängigkeit
- Nicht alle Hardware-Features sind in VMs vollständig nutzbar (z. B. GPU-Passthrough eingeschränkt)
- Abhängigkeit vom Hypervisor-Anbieter (**Vendor Lock-in**)

### ❌ Speicherbedarf
- Jede VM benötigt ein vollständiges Betriebssystem → **hoher Speicherbedarf**
- Snapshots und Backups können schnell viel Festplattenspeicher belegen

## 📌 7. Hypervisor vs. Container

| Merkmal            | Hypervisor (VM)                  | Container (z. B. Docker)         |
|--------------------|----------------------------------|----------------------------------|
| Isolation          | Vollständige Isolation           | Prozess-Level-Isolation          |
| OS pro Einheit     | Eigenes vollständiges OS         | Teilen Host-Kernel               |
| Startzeit          | Minuten                          | Sekunden                         |
| Größe              | GB (inkl. OS)                    | MB (nur App + Dependencies)      |
| Performance        | Overhead durch Hypervisor        | Nahezu native Performance        |
| Sicherheit         | Sehr hoch (starke Isolation)     | Geringer (geteilter Kernel)      |
| Einsatz            | Verschiedene OS, Enterprise      | Microservices, DevOps, Cloud     |

## 📌 9. Zusammenfassung

```
Hypervisor = Software, die physische Hardware in mehrere virtuelle Maschinen aufteilt

Typ 1 (Bare-Metal) → direkt auf Hardware → hohe Performance → Rechenzentren
Typ 2 (Hosted)     → auf Host-OS        → einfache Nutzung → Entwicklung/Tests

Vorteile: Ressourcenoptimierung, Kostenersparnis, Flexibilität, Ausfallsicherheit
Nachteile: Performance-Overhead, Komplexität, Sicherheitsrisiken, Lizenzkosten
```
